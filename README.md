# 가상 노드 일관 해시 링

물리 노드 A~D에 키 10만 개를 배정한 뒤 E를 추가하거나 B를 제거해 담당자가 바뀐 키를 센다. 두 변경은 같은 최초 배치에서 각각 시작한다.

## 실행

JDK 21과 POSIX 셸에서 저장소 루트의 `./scripts/verify.sh`를 실행한다. 첫 빌드는 Gradle과 JUnit을 내려받는다. 테스트·빌드 후 실험을 두 번 실행해 키별 세 배치와 결과 표가 바이트 단위로 일치하는지 확인한다. 출력 파일은 `build/verification/`에 있다. 빌드 후 실험만 실행하려면 `java -jar build/libs/consistent-hash-ring.jar`를 사용한다.

## 배정과 측정

키 문자열은 key-0부터 key-99999까지다. 토큰 입력은 십진 시드, 노드 이름, 0부터 시작하는 가상 노드 순번을 콜론으로 연결한다. 두 입력 모두 UTF-8 → SHA-256 → 앞 8바이트를 빅엔디언 부호 없는 정수로 읽는다. 키 좌표 이상의 첫 토큰을 고르고 끝에서는 처음으로 돌아간다. 토큰 충돌은 변경 전체를 거부한다.

최대/평균은 가장 많은 키를 맡은 노드의 키 수를 25,000으로 나눈 값이다. 이동률은 물리 노드가 바뀐 키 수를 100,000으로 나눈 값이다. 실험은 추가 시 모든 이동의 목적지가 E인지, 제거 시 모든 이동의 출발지가 B인지, 유입·유출 합과 이동 수가 같은지 확인한다. E 제거 후 모든 키의 최초 배치 복원도 검사한다.

시드 1, 가상 노드 1개에서 E 추가 전후의 경로 (16진수 좌표)

- key-24 (30beff1493d31bf8) → B (b7ced8bab516345b) → E (397a97d0c1c4655e)
- key-0 (d5ead6fdd3d16630) → A (308784b942cd8052) → A (308784b942cd8052)

key-24의 시계 방향 경로에 B보다 가까운 E 토큰이 생겨 E로 이동했다. key-0은 마지막 토큰 뒤에서 링의 처음으로 돌아가 A를 만난다. E는 A 뒤에 들어와 담당자가 유지됐다.

이 다섯 시드에서 가상 노드를 1개에서 128개로 늘리자 최대/평균의 평균은 1.9072에서 1.1473으로 내려갔다. B 제거 이동률은 최초 B의 점유율과 같다. 그래서 16개에서 128개로 늘릴 때 쏠림은 줄었어도 B 제거 평균 이동률은 25.587%에서 27.096%로 올랐다. 이 수치는 고정 키 집합과 시드 다섯 개에서 측정한 결과다. 실제 데이터 전송·복제·장애 복구는 모의하지 않는다.
